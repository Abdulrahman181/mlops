# Telecom Customer Churn Prediction

This repository contains an exploratory training notebook and a Streamlit dashboard for a telecom customer-churn classifier. **The repository does not include customer data or trained model artifacts.** No synthetic data or replacement models are generated by the application.

## Repository status

- `Customer_Churn_Prediction.ipynb` contains the training/EDA workflow.
- `main.py` is the prediction dashboard.
- `Deployment_Churn/` is expected at runtime but is intentionally ignored by Git because pickles can contain executable code and may encode sensitive artifacts.
- The notebook now uses a local path or `TELCO_DATA_PATH`; it stops with an actionable `FileNotFoundError` when the CSV is unavailable.

## Setup

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## Train / inspect the notebook

Obtain the trusted Telco Customer Churn CSV outside this repository and set its path:

```bash
export TELCO_DATA_PATH=/absolute/path/WA_Fn-UseC_-Telco-Customer-Churn.csv
jupyter notebook Customer_Churn_Prediction.ipynb
```

The notebook validates the input columns and target labels, uses a fixed, stratified train/validation/test split (`random_state=42`), and fits `StandardScaler` on the training partition only. It does not claim a model score until it is run with the real dataset.

## Run the dashboard

Export the trained encoders, scaler, and models from a trusted training environment under the following layout:

```text
Deployment_Churn/
├── Encoding/InternetService_le.pkl
├── Encoding/PaymentMethod_le.pkl
├── Encoding/Contract_oe.pkl
├── Scaling/scaler.pkl
└── Models/{Decision Tree,LogisticRegression,SVC,KNN,RandomForest,GradientBoosting,XGBoost,AdaBoost,Stacking}.pkl
```

Then run:

```bash
streamlit run main.py
```

If any artifact is missing or invalid, the app displays a clear error and performs no prediction. **Never load untrusted pickle files**; pickle deserialization can execute code.

## Validation

```bash
ruff check main.py tests
pytest -q
python -m py_compile main.py tests/test_repo_health.py
```

The tests verify Python parsing, notebook JSON/output hygiene, and the missing-artifact failure path. They do not replace training or validate model quality.

## Known limitations

- Model quality, calibration, threshold choice, and fairness cannot be assessed without the original dataset and a reproducible training run.
- The dashboard mirrors the notebook's exact 18-feature order, including its omission of `gender`: `SeniorCitizen`, `Partner`, `Dependents`, `tenure`, the service fields, `Contract`, `PaperlessBilling`, `PaymentMethod`, `MonthlyCharges`, and `TotalCharges`. The scaler is applied to all 18 columns, as it is during training.
- Model comparison is based on validation accuracy; test metrics are reported for inspection but are not used to select a production model. The notebook still does not provide confidence intervals, calibration, threshold tuning, fairness checks, or a separately locked final test protocol.
- Retraining should export artifacts with an explicit schema/version manifest and should pin the exact training environment before production use.
